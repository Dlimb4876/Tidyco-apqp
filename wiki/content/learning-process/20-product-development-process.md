# Product Development Process Workflow

## Primary workflow
1. Open [NPI Projects](../product-development/10-npi-projects.md) and select the project.
2. Build APQP sequence in order: CTQ -> PFD -> PFMEA -> Control Plan.
3. Create and track actions and risks.
4. Maintain timing and gate readiness evidence.
5. Complete gate sign-off with required roles.

## Recommended execution sequence
| Sequence | Activity | Why this order matters |
|---|---|---|
| 1 | CTQ | Defines what quality must be controlled |
| 2 | PFD | Defines process flow and where failure can occur |
| 3 | PFMEA | Quantifies risk and prioritises mitigation |
| 4 | Control Plan | Converts risk decisions into control checks |
| 5 | Actions/Risks | Tracks closure and accountability |
| 6 | Gates | Formal readiness decision point |

## PFMEA site workflow
For click-path and field usage details, use [PFMEA in Tidyco: Tool Workflow](../product-development/51-pfmea-tool-workflow.md).

## Gate readiness handoff
Before requesting gate sign-off, confirm:
- open high-risk items have owners and due dates
- linked evidence is current version
- action backlog does not hide unresolved blockers
- timing plan reflects current reality

## Common process breaks
- Building PFMEA before stable PFD structure
- Leaving actions open but still requesting gate approval
- Uploading evidence without clear traceability to gate criteria
- Using stale timing assumptions after scope change
