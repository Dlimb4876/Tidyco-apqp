# Feedback and Bugs Process Workflow

## Primary workflow
1. Submit issue with clear context and impact.
2. Triage and classify.
3. Assign owner and target date.
4. Update status through investigation and fix.
5. Close with visible resolution notes.

## Quality bar for submissions
- Reproducible steps included
- Environment and role included
- Evidence attached (screenshot/log/reference)
- Single issue per report

## Triage model
1. Classify type (bug, enhancement, data, performance, usability).
2. Set realistic priority from business impact.
3. Assign owner and target date.
4. Link related module or record references.

## Common process failures
- Multi-issue reports that cannot be assigned cleanly
- Missing reproduction detail
- Priority inflation without business context
