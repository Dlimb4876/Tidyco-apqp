# Settings Process Workflow

## Primary workflow
1. Review current configuration scope before editing.
2. Update structural data first (work areas, teams, departments).
3. Update local preferences after structural updates.
4. Verify downstream pages behave as expected.

## Scope-first decision step
Before changing anything, classify as:
- **Global:** affects all users or planning logic
- **Local:** affects only your current device/browser

## Safe change sequence
1. Confirm requirement and affected teams.
2. Apply change in Settings.
3. Validate one impacted downstream page.
4. Communicate if the change is global.
5. Recheck after first user session.

## Common process failures
- Applying local preferences expecting global effect
- Editing team/permission structures without validation
- Making global naming changes without communication
