# Raising Change Requests

## What this page is for
Use this page when creating a new MCS request so approvals are faster and rework is lower.

## When to raise an MCS request
Raise an MCS item when the proposed change affects:
- product definition
- process method
- tooling or test method
- quality, safety, or compliance expectations

If the change is only editorial with no operational effect, confirm whether a full MCS is still required by your local governance.

## Request quality checklist
Before submitting, make sure your request includes:
- clear current-state problem statement
- proposed change in plain language
- impacted teams and locations
- known risks and dependencies
- expected implementation window

## Step-by-step request workflow
1. Open **MCS** and click **New Request**.
2. Pick the correct **Change Type** (Emergency, Major, Minor, Administrative).
3. Write the problem and proposed change clearly.
4. Complete impact fields for quality, operations, and supply chain.
5. Add initial implementation outline and expected effort.
6. Save, then route for first-stage approval.

## Writing strong justifications
Good justification answers three questions:
1. What is wrong today?
2. Why this change is the right response?
3. What happens if no change is made?

Keep it evidence-based (defects, delays, safety incidents, audit findings, etc.).

## Common rejection reasons
- Change scope is vague
- Impact assessment is incomplete
- No rollback or containment thought process
- Approval roles not aligned to affected functions

## Basic planning calculations
### Estimated implementation effort
```text
Total Estimated Hours = Engineering + Production + Validation + Documentation
```

### Estimated schedule shift
```text
Schedule Shift (days) = Proposed Completion Date - Baseline Completion Date
```

### Approval readiness score (simple check)
```text
Readiness % = (Completed Required Fields / Total Required Fields) × 100
```

Use this as a quick quality gate before routing to approvers.
