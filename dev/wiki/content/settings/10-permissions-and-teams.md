# Permissions and Teams

## What this page is for
Use this page when you need to control who can see, edit, and approve work in Tidyco APQP.

This is where role setup and team membership become practical daily access.

## When to update permissions or teams
- A new starter joins the business
- Someone changes department or role
- A person starts approving gates or MCS changes
- A team can see too much or too little

## Before you make changes
- Confirm whether the change is permanent or temporary
- Check if access should apply across all portals or only specific areas
- Confirm who owns final sign-off for sensitive approvals

## Practical update workflow
1. Open **Settings** and go to **Permissions & Teams**.
2. Find the person account and verify current team.
3. Update team and role-based access in the same session.
4. Save changes and ask the user to refresh once.
5. Verify expected visibility in the target portal.

## What each permission should mean (plain language)
| Permission Type | Plain-language meaning | Typical owner |
|---|---|---|
| View access | Person can open that area and read data | Most active users |
| Edit access | Person can change records in that area | Team leads or operators |
| Approval access | Person can sign off gates or formal changes | Named approvers |
| Admin access | Person can change shared configuration | Platform admins |

## Team assignment guidance
- Put users in the team that matches their **actual day-to-day stream** (ME, PM, Logistics, Unit 6, etc.).
- Avoid dual-team membership unless the role is genuinely cross-functional.
- If a user temporarily covers another team, set a review date to remove extra access.

## Common mistakes to avoid
- Granting Admin when Edit is enough
- Forgetting to assign a team after creating a user
- Leaving old approvals active after role changes
- Changing permissions without telling affected team leaders

## Quick validation checklist
- [ ] User can open only the portals they should access
- [ ] User can edit where required and nowhere else
- [ ] Approval queues show only valid approvers
- [ ] No orphan users without team assignment
